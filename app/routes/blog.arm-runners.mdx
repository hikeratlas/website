# GitHub Actions: ARM runners are 1.5x faster for tilemaker (Nov 2, 2026)


_Disclosure: Claude Code ran the experiments described here, and Claude wrote the post's initial draft. It was reviewed and edited by me._

The Hiker Atlas map is built on [GitHub Actions](/blog/github-actions), using the free runners you get for a public repo. Their stated specs are the same whether you ask for x64 (`ubuntu-latest`) or ARM (`ubuntu-24.04-arm`): 4 vCPUs and 16 GB of RAM.

Of course, 4 vCPUs on ARM and 4 vCPUs on x64 are two very different things. (And, it turns out, the "same" 4 vCPUs on x64 on repeated runs are several very different things!)

## The x64 lottery

I added a step that logs the hardware each job lands on. GitHub serves VMs for `ubuntu-latest` runners from a pool of instance types. In one run, the 9 layer jobs landed on four different Azure VM kinds:

- `D4ads_v5`: AMD EPYC 7763
- `D4ads_v6`: AMD EPYC 9V74
- `D4ads_v7`: AMD EPYC 9V45
- `D4ds_v5`: Intel Xeon 8370C

As the saying goes, you get what you get, and you don't get upset.

But it kind of sucks: the same tilemaker job takes about 1.5x longer on an older v5 than on a v7:

  <img src="/arm-runners-x64-lottery.png"/>
</div>

This makes it a bit challenging to benchmark build times to catch regressions. How fast a build performs is like 50% the code it ran and 50% the machine running the code.

## ARM

GitHub also offers ARM runners. Maybe they perform better? Or at least more consistently, for profiling?

I built all 9 North America layers on both runner types, side by side:

<div className="flex justify-center items-center">
  <img src="/arm-runners-layers.png"/>
</div>

ARM was faster on every layer, **1.48x overall**. The `ways` layer, which decides when the layer stage finishes, dropped from 29 minutes to under 20.

Look at `parks`: only 1.12x. Its x64 job happened to draw a v7, the fastest x64 VM. Against the slower v5s, ARM was 1.4–1.6x faster.

So, faster! That's great.

But also, more predictable: all 9 ARM jobs landed on the same VM type, `D4pds_v6`, and so has every ARM job I've checked since. I'm sure eventually GitHub's
collection of ARM runners will become heterogeneous, but for now, it's a nice bonus that they're predictable.

## Caveats

Today, as long as your code can run on ARM, there's no downside to switching to the `ubuntu-24.04-arm` runners.
